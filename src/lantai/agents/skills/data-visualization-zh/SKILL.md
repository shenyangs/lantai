# 数据可视化

先确认数据口径和图表要回答的问题，再选择图形。图表不是装饰；没有可靠数据时先说明缺口，不要补造数值。

## 工作流

1. 识别数据来源、字段、单位、时间范围、缺失值和统计粒度。
2. 用一句话写清读者要比较、观察或判断什么。
3. 按 `references/chart-contract.md` 选择图形和编码。
4. 检查分母、时间顺序、分类顺序、零基线和异常值。
5. 在普通解释之后输出一个 `echarts` 围栏，只放严格 JSON。
6. 检查 JSON 可解析，标题与可见编码一致，数值与原始数据一致。

数据量小且一眼可读时优先用 Markdown 表格，不强行画图。数据不足时先提最小澄清问题，或明确标注示例数据；绝不把示例伪装成真实结果。

## 澜台图表协议

只允许下面两种形式：

- 直接输出 ECharts `option` JSON。
- 输出澜台信封：`title`、可选 `description`、可选 `height`、必需 `option`。

推荐信封格式：

````markdown
```echarts
{
  "title": "月度收入",
  "description": "单位：万元；按确认收入月份统计",
  "height": 360,
  "option": {
    "tooltip": {"trigger": "axis"},
    "grid": {"left": 48, "right": 24, "top": 36, "bottom": 42},
    "xAxis": {"type": "category", "data": ["1月", "2月", "3月"]},
    "yAxis": {"type": "value", "name": "万元"},
    "series": [{"name": "收入", "type": "bar", "data": [128, 156, 149]}]
  }
}
```
````

宿主当前支持 `bar`、`line`、`pie`、`scatter`、`radar` 及常见标题、图例、坐标轴、提示、缩放、数据集和标记组件。

## 安全边界

- 只输出 JSON；不输出函数、JavaScript 表达式、HTML、`eval` 或事件处理器。
- 不通过 `symbol`、`icon` 或其他字段加载远程、`data:`、`file:` 图像。
- 不写 `__proto__`、`prototype`、`constructor` 字段。
- 配置应小于 200 KB，嵌套不超过 24 层；过大的原始数据先聚合或抽样并说明。
- 不把密钥、个人联系信息、支付信息或未脱敏的敏感数据放入图表。

若宿主拒绝配置，先修正 JSON；无法可靠修正时改用紧凑 Markdown 表格，不绕过安全限制。

## 质量门槛

- 标题中写“按某维度”时，该维度必须出现在坐标轴、颜色/系列、分面或直接标签中。
- 多系列图必须有可见图例或直接标签。
- 时间轴按时间排序；分类条形图按读者任务选择逻辑排序。
- 柱状图默认从零起；确需截断必须明确标注。
- 饼图只用于少量互斥部分构成整体，避免过多扇区。
- 散点图保持一行一个可解释观察对象，并保留标签、样本量或权重字段（如有）。
- 单位、口径、时间范围和重要排除项写在说明或正文，不塞进来源不明的“洞察型”标题。
