# 浏览器测试

使用澜台 `browser_use` 和浏览器工作台，不依赖外部 `playwright-cli`、临时 `npx` 命令或第三方会话服务。

## 1. 建立测试契约

读取 [test-plan.md](references/test-plan.md)，确定：

- 入口 URL 与运行命令；
- 关键用户流程和成功条件；
- 允许修改的数据与禁止操作；
- 桌面/窄屏尺寸；
- 是否可使用现有登录态；
- 需要保存的截图、日志和复现步骤。

## 2. 启动

- 默认使用 managed CDP；需要隔离会话时使用 `private_mode=true`。
- 页面依赖本地服务时，先检查端口与健康状态。
- 登录、验证码、支付和真实发布由用户完成或明确授权。

## 3. 执行

1. 打开入口并等待稳定状态。
2. 从语义快照定位元素，按用户路径操作。
3. 每个关键步骤检查 URL、可见状态、禁用状态和错误提示。
4. 检查控制台错误、失败请求、空态和异常输入。
5. 在主要桌面宽度和至少一个窄屏尺寸复跑关键页面。
6. 视觉任务保存截图；动态或偶发问题记录时间与复现频率。

## 4. 失败处理

- 区分产品失败、测试环境失败、账号权限和数据前置条件。
- 自动重试只用于明确的暂态加载，不能用重试掩盖稳定缺陷。
- 复现失败时保留最后成功步骤、当前 URL、可见错误和相关日志。

## 5. 交付

按“通过、失败、阻塞、未覆盖”列出用例。每个失败包含复现步骤、预期、实际、证据和影响。不要声称“全部通过”而省略未执行项。

## 停止条件

关键流程实际运行、证据已保存、失败可复现或明确阻塞原因、测试没有留下未经授权的外部数据变更。
