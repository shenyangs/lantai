# 精简代码审查

当用户问“这段是否过度设计”“还能删什么”“有没有重复造轮子”“做一次精简审查”时使用。本 Skill 是对常规正确性/安全审查的补充，不替代它。

## 审查目标

只找可删除、可替换或可收缩的复杂度：

- 无调用方的死代码、无用灵活性或推测性功能；
- 手写但标准库已经提供的实现；
- 依赖或自定义代码替代了平台原生能力；
- 只有一个实现、一个调用方或从未设置的配置所支撑的抽象；
- 逻辑不变但可以明显缩短的实现。

先读完整 diff 及其必要上下文，确认行为和边界；不要把“短”误判成“正确”。测试、输入验证、权限/安全、数据保护、可访问性和已说明的兼容约束不是可删的样板。

## 输出合同

默认只读，不直接修改代码。每个发现一行，使用以下格式：

```text
<文件>:L<行号或范围>: <delete|stdlib|native|yagni|shrink>: <该删什么>。<替代方案或“无需替代”。>
```

最后给出 `预计净减少：-N 行`；无法可靠估算时写“无法安全估算”。若没有可减项，只输出：`已经足够精简，可以提交。`

## 边界

- 只找可删除的复杂度；正确性缺陷、性能瓶颈和安全漏洞转交常规审查，不混成一张问题清单。
- 不建议删掉聚焦测试或最小 smoke；它们是精简实现的验证底线。
- 若用户要求实施，再回到编码流程，逐项确认影响并运行相应验证。
