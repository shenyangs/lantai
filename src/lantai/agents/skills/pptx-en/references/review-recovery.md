# Review, repair, and recovery

1. Render the serialized final PPTX, not an undelivered HTML page, authoring canvas, or screenshot surrogate.
2. Run deterministic checks before visual critique on every slide. Every final slide needs evidence bound to its current hash. Separately review deck narrative, repetition, rhythm, transitions, and whether the central judgment is visible.
3. Use controlled concurrency only for bounded critic calls; never reduce full verification. Passing per-slide checkpoints may be cached. Invalidate every dependent page when page content, a shared asset, theme, or data changes.
4. Rerender a repaired slide. Rerun deck review when narrative structure, order, or global direction changes. Never omit the last repaired slide from review.
5. Keep content, geometry, aesthetics, file, model-service, and authorization errors distinct. Do not escape a failure by forcing the user to accept fewer slides or an outline.
6. `get_presentation_generation_status` is read-only. Call `retry_presentation_generation` on the original `job_id` only when every persisted route on the latest failure permits automatic recovery; never blind-rerun content, geometry, aesthetic, authorization, or unclassified failures. Call `finalize_presentation_generation` only when `publish_ready` and the user still wants that delivery. Label any usable draft preview as not formally passed.
7. Source-index failures are pure pre-generation argument validation: no job or output file has been created. Use `source_index_repair` to correct the file list and storyboard mappings together, preserving real sources. `source_indexes` are zero-based FILE indexes, not PDF page numbers. Evidence-content failures use `grounding_repair`; never fabricate or erase sources.
8. Follow `delivery_repair` for visual delivery failures; ordinary `view_image` and prose acceptance claims cannot stand in for system-owned full-page review. Preserve the candidate and use a successful same-attempt canonical generation result and its real render paths. With no qualified job, correct the original input and generate under a new filename. Inspect the original job for unknown outcomes, without duplicate generation. A failure is not authorization to silently restart a task the user stopped.
