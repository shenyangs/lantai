# Skill 审核策略

## 保留

能力常见、输入输出稳定、能完全使用澜台现有工具运行，并且没有更好的内置实现。

## 合并

与已有 Skill 任务对象相同，只是补充了流程、模板或质量门。把有效部分并入原 Skill，避免增加宽泛触发器。

## 原生重写

核心方法独立成立，但原包包含其他平台工具名、路径、输出协议、安装器或许可不清内容。根据期望行为重新编写，不复制正文和资产。

## 暂缓

方法合理，但澜台还没有可靠宿主、运行时或权限模型。先列出产品前置条件，不预置一个无法兑现的 Skill。

## 放弃

离开原平台专有宿主就失去主要价值，或必须依赖无法审计、无法分发、风险过高的运行组件。

## 高风险信号

- 自动安装依赖或下载后执行；
- 凭证写入 Skill 目录；
- 未声明的远程 API 或数据上传；
- 超大二进制、WASM、模型和缓存；
- 描述宽泛到能覆盖大多数任务；
- 没有停止条件或验证步骤；
- 明确禁止再分发或缺少必要许可。
