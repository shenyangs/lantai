# Skill 体检

使用本技能自带的只读扫描器检查 Skill，不调用 WPS API，不读取或上传凭证。

## 运行

```bash
python scripts/scan_skills.py --root /path/to/skills --format markdown
```

多个来源重复传入 `--root`。需要机器可读结果时使用 `--format json --output report.json`。CI 中可增加 `--fail-on error` 或 `--fail-on warning`。

## 审核顺序

1. 运行扫描器，保留完整结果。
2. 对错误逐项打开原文件确认，避免只根据关键词误判。
3. 用 [review-policy.md](references/review-policy.md) 区分：
   - 可直接修复的规范问题；
   - 应并入现有 Skill 的触发重叠；
   - 能原生重写的方法；
   - 必须放弃的平台私有能力。
4. 给出“保留、合并、重写、暂缓、放弃”结论和具体文件。
5. 只有用户要求修复时才修改文件；体检本身保持只读。

## 第三方 Skill 安全导入

外部 Skill 先审后装，扫描通过不等于代码可信：

1. 记录仓库/发布页、作者、许可证、版本或提交、下载时间和校验和；拒绝来源不明、许可不清或只给可变 latest 链接的包。
2. 在隔离的临时目录解包，先检查 `SKILL.md`、脚本、二进制、符号链接、隐藏文件、安装钩子、网络下载和凭证读取；不要为了“看看能否运行”先执行脚本。
3. 用本技能扫描器审查临时目录，并人工确认高风险命中、触发描述、工具名和相对链接。
4. 对照现有 Skill，决定保留、合并、原生重写或放弃。与内置 Skill 同名或触发高度重叠时不覆盖原包。
5. 用户明确要求安装时，不把澜台管理界面当成唯一入口。当前 Agent 优先调用 `install_agent_skill(source, enable=false)`；`source` 可以是当前主题工作区内的目录、ZIP 或固定 HTTP(S) URL，全部经过同一套暂存、结构校验、安全扫描和冲突检查。
6. 命令行也可使用 `lantai skills install <目录|zip|url> --agent-id <id> --no-enable`。复核清单和差异后启用；启用成功后当前轮即可用 `read_skill` 读取，下一轮会进入 Skill 目录。
7. 用 `lantai skills test <skill> --agent-id <id>` 做结构校验，再以无秘密、无外部写入的正向/负向任务验证触发。界面只是等价的人工管理入口，不是安装的前置条件。

外部 CLI 遵循同一原则：用户明确要求安装时，可以使用厂商安装器或标准包管理器在用户级/项目级安装，随后验证 `command -v`、版本和一个无副作用命令并继续原任务；除非用户明确要求，不使用 `sudo` 或系统级覆盖。不得静默安装运行时、绕过扫描、复制真实凭证、执行未知安装脚本或自动覆盖同名 Skill。

接入 MCP 时优先调用 `manage_mcp_connector` 走澜台受保护控制面；配置写入当前主题工作区的 JSON 文件后再传文件路径，避免把密钥暴露在工具参数和对话轨迹中。该入口与设置页共用校验、密钥遮罩、持久化和热重载。

## 输出

- 摘要：Skill 数、错误、警告、重叠对。
- 明细：规则、严重级别、文件、可执行建议。
- 依赖：运行时、网络、凭证和宿主要求。
- 处置表：保留/合并/重写/暂缓/放弃。
- 导入记录：来源、固定版本、许可证、校验和、扫描结果、启用状态和回滚方式。

## 边界

关键词命中只是风险线索，不等于漏洞。不得在报告中输出检测到的凭证值。扫描器只报告文件和规则名称。第三方脚本只有在人工确认并获得必要授权后才能运行；无法核实来源、许可或副作用时停止导入。
