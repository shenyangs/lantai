# Liaison 分享本地作品

当用户说“分享这个页面”“把 localhost 给别人看”“发给客户预览”“让手机访问这个本地网页”“把生成的 HTML/PPT/API 暂时公开一下”等，使用本技能。

## Liaison 是什么

Liaison 是开源的安全反向代理 / 内网应用访问方案，适合把本机、家庭、办公室或内网里的设备与应用通过受控入口给外部访问。它支持 HTTP/HTTPS、WebSocket、TCP 等应用代理，也强调 TLS 加密、来源 IP 白名单、流量监控和随时开启关闭。

来源：https://github.com/liaisonio/liaison

## 判断流程

1. 明确要分享的对象：静态 HTML 文件、Vite/Next/Flask/FastAPI 等本地服务、API、仪表盘、图片目录或其他内网服务。
2. 确认当前服务状态：本地端口、路径、登录状态、是否包含隐私数据、是否已经能在本机正常打开。
3. 分享前必须向用户说明将暴露的本地地址、端口、路径和风险，并得到明确授权。
4. 优先分享只读预览页面；不要分享工作区根目录、系统配置、密钥、数据库管理后台、私人聊天记录或内网管理面板。
5. 如果用户只是想本机查看，直接提供本地 URL，不使用 Liaison。
6. 如果用户没有安装或配置 Liaison，说明需要先部署服务端并安装连接器；不要替用户下载或运行未知二进制，除非用户明确授权。

## 推荐操作

- 静态 HTML：先用本地静态服务器只服务目标目录，再通过 Liaison 暴露该本地地址。
- 已运行的开发服务：复用当前端口，例如 `http://127.0.0.1:5173`，不要启动重复服务。
- API 服务：只开放演示或文档 endpoint，提醒用户不要暴露写入、删除、管理类接口。
- 文件分享：优先把文件放到专门的只读目录，不要暴露整个工作区。
- 分享前检查页面：确认不是错误页、不是登录态隐私页、资源能正常加载。
- 分享后告诉用户：公开访问地址、暴露范围、有效期或停止方式。

## 安全边界

- 外部分享默认需要用户确认；没有明确授权时，只能解释方案和本地预览方式。
- 发现密钥、token、cookie、个人聊天、客户资料或未脱敏数据时，先提醒用户处理，不继续分享。
- 不承诺 Liaison 是长期托管平台；它适合受控访问和临时预览，长期发布应使用正式部署或对象存储。
- 如果 Liaison 入口支持白名单、有效期、登录或访问控制，优先建议用户开启。

## 回复模板

确认可分享时：

> 我会用 Liaison 暴露 `本地地址` 的只读预览，外部访问范围是 `范围`。这里可能会让互联网上持有链接的人访问该页面，确认继续吗？

完成后：

> 已准备好分享链接：`URL`。当前暴露的是 `范围`；结束分享时请在 Liaison 控制台关闭对应入口，或停止本地服务。
