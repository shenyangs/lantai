# MCP transport 与安全检查

## transport

### stdio

- command 使用已解析的可执行文件，不通过 shell 拼接不可信参数；
- args 逐项传递，cwd 指向明确目录；
- env 只包含必需变量，秘密不出现在 args；
- 处理子进程退出、stderr、启动超时和孤儿进程。

### Streamable HTTP / SSE

- 使用 HTTPS，校验最终 URL、重定向和证书；
- 默认拒绝 loopback、链路本地、内网和云元数据地址；
- headers 中的秘密必须掩码；
- 设置连接/读取超时、响应大小上限和可控重试；
- OAuth 使用 Authorization Code + PKCE，并验证 state、过期和刷新失败。

## 工具合同

每个工具必须回答：

- 名称和描述是否让模型能与相邻工具区分？
- schema 是否限制类型、必填项、枚举、长度和未知字段？
- 输出是否稳定、可截断、能表达部分成功？
- 哪些调用有外部副作用，是否幂等，是否需要确认？
- 路径、URL、查询和命令是否在服务端再次校验？
- 错误是否分为可重试、需重新认证、配置错误和永久失败？

## 上线门

- 版本或提交已固定，来源和许可已核实；
- `allowed_tools` 仅含任务需要的工具；
- 未授权私网访问保持关闭；
- 正常、非法输入、缺凭证、超时、取消和敏感输出测试完成；
- probe、lifecycle 与工具列表一致；
- 启用、禁用和回滚均有实际步骤。
