# 审查、修复与恢复

1. 从已序列化的最终 PPTX 渲染，不审未交付的 HTML、作者 canvas 或截图替身。
2. 每页先跑确定性检查，再做视觉 critic；所有最终页都必须有与当前页哈希绑定的证据。整套另审叙事、重复、节奏、转场和主判断是否突出。
3. 并发只用于限定 critic 调用，不降低全量验真。通过的页级 checkpoint 可缓存；页内容、共享资源、主题或数据变化时必须失效所有依赖页。
4. 修复一页后必须重新渲染该页；改变叙事结构、页序或全局视觉时重跑整套审查。最后一次修复后的页不得漏检。
5. 内容、几何、审美、文件、模型服务和授权错误保持分类。不要用缩页数或改为提纲来逃避故障。
6. `get_presentation_generation_status` 只读返回状态。只有最新失败事件的全部持久化路由均允许自动恢复时，才对原 `job_id` 调用 `retry_presentation_generation`；内容、几何、审美、授权和未分类故障不得盲重跑。只有 `publish_ready` 且用户仍需要该交付时，才调用 `finalize_presentation_generation`。草稿预览必须明示“未正式通过”。
7. 来源索引错误属于生成前的纯入参校验，未创建 job 或输出文件。按 `source_index_repair` 一并修正文件列表和故事板对应关系，保留真实来源；`source_indexes` 是从 0 开始的文件索引，不是 PDF 页码。证据内容错误另按 `grounding_repair` 修订，不编造或删除来源。
8. 交付视觉失败按 `delivery_repair` 恢复，不用普通 `view_image` 或验收文案伪造系统全页审查。保留已有候选，使用同轮规范生成工具的成功结果及其真实渲染路径；缺少合格 job 时修正原输入、另取文件名生成。未知结果先查原 job，不重复启动；失败不等于 Stop 授权，不得暗中重启用户停止的任务。
