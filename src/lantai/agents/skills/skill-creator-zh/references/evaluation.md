# Skill 评测方法

## 评测集

| 类型 | 最少数量 | 关注点 |
|---|---:|---|
| 正向触发 | 3 | 描述能覆盖常见说法和文件类型 |
| 负向触发 | 3 | 不与相邻 Skill 抢任务 |
| 缺失输入 | 2 | 能继续安全推进或明确停止 |
| 权限边界 | 1 | 不擅自发布、发送、删除或覆盖 |
| 真实产物 | 1 | 输出能打开、能复核、满足停止条件 |

## 评价维度

1. **触发准确度**：该触发时触发，不该触发时保持安静。
2. **完成度**：产物满足用户任务，而不是只复述流程。
3. **可验证性**：包含来源、测试、预览或结构化检查。
4. **可移植性**：不依赖作者机器、私有目录或未声明服务。
5. **安全性**：凭证、隐私、外部写入和破坏性操作有边界。
6. **上下文成本**：SKILL.md 足够短，详细内容按需加载。

## 迭代

- 触发过宽：收紧 description 的正向对象和负向边界。
- 触发过窄：补用户真实说法，不堆同义词列表。
- 步骤常漏：把脆弱步骤改成检查表或确定性脚本。
- 输出漂移：加入结构化输出契约和停止条件。
- 依赖失败：提供澜台原生降级；不能降级则明确放弃该能力。
