# Skill 创建与评测

创建小而明确、能被正确触发、能在澜台实际运行的 Skill。默认写澜台原生工作流，不复制未知许可内容，不依赖其他产品私有宿主。

## 1. 定义契约

在写文件前明确：

- 用户会怎样表达请求；
- 什么情况必须触发，什么情况不得触发；
- 稳定输入、输出和停止条件；
- 需要哪些澜台工具、连接器、权限和外部凭证；
- 是否已有 Skill 能通过扩展覆盖，避免重复创建。

## 2. 选择最小结构

```text
skill-name/
├── SKILL.md
├── references/   # 仅放按需读取的详细规则
├── scripts/      # 仅放需要确定性的重复逻辑
└── assets/       # 仅放交付时会复用的资源
```

只有 `SKILL.md` 必需。不要加入 README、安装指南、变更日志、旧输出或演示缓存。

## 3. 编写

- 文件夹使用小写字母、数字和连字符；名称简短且以动作或能力为中心。
- frontmatter 的 `description` 同时写清能力、正向触发和关键负向边界。
- 正文使用祈使句，保留非显而易见的流程、质量门和失败处理。
- 只引用澜台实际存在的工具。外部命令必须先探测，不能在 Skill 中自动安装。
- 破坏性、对外发布、覆盖文件、发送消息和高风险判断必须保留确认点。
- 详细变体放入一层 `references/`，避免深层引用和正文重复。

## 4. 原生化检查

拒绝以下内容：

- WPS/Comate/AppBase 的私有目录、宿主路径或私有工具调用；
- 依赖特定聊天宿主才能显示的未知标签或代码块；
- 静默安装运行时依赖或下载后执行脚本；
- 凭证、Cookie、个人路径、旧产物或不可再分发资产；
- 没有明确许可的第三方正文和数据集直接复制。

方法可以独立成立时，按目标行为重新编写，并使用澜台工具完成。

## 5. 评测

读取 [evaluation.md](references/evaluation.md)，至少准备：

- 3 个应触发任务；
- 3 个不应触发的邻近任务；
- 2 个输入缺失或工具不可用的失败任务；
- 1 个涉及权限或隐私的边界任务。

先做静态校验，再用真实任务前向测试。复杂 Skill 的通过标准必须包含产物质量，不只看是否触发。

## 6. 交付

报告新增或修改的文件、触发边界、依赖、验证结果和未覆盖风险。未经用户授权，不上传市场、不覆盖已有同名 Skill。

## 停止条件

结构校验通过、引用无断链、脚本实际运行、正负触发样例符合预期、没有私有宿主或隐式安装依赖。
