# 开源仓库研究评审表

## 证据层级

1. 已读取的源码、schema、测试、CI 和官方发布产物。
2. 维护者文档、issue、PR、discussion 和 release note。
3. 可复现的静态行为、公开客户端资产与 API 契约。
4. 第三方文章、视频和搜索摘要，只用于发现线索。

对每个关键主张记录：证据、层级、固定版本/日期、直接支持还是推断、限制。

## 架构评审

- 用户可见入口与运行入口是否匹配？
- 调用链中的编排、领域规则、adapter、store 和渲染/导出边界在哪里？
- 核心数据合同是什么？谁创建、修改、验证它？
- 长任务如何表示阶段、进度、重试、恢复、取消与幂等？
- 交互式编辑是全量重算还是局部失效？
- 核心能力是开源实现、外部 API、托管服务还是未知？

## 工程与运行风险

- 安装与运行时依赖；是否要求未声明的外部服务。
- lockfile、可复现构建、测试类型与 CI 覆盖。
- 最近发布、破坏性变更、issue 积压与单一维护者风险。
- 网络、文件、shell、凭证、浏览器、本地服务和外部写入权限。
- 隐私数据、遥测、训练数据声明和本地/云端边界。

## 许可证与借鉴边界

- 确认 LICENSE 文件和目标 revision，不只看 README 徽章。
- 分开代码许可、模板/字体/图片/音频等资产许可和商标。
- “公开可读”不等于“可复制进产品”。许可不明时只做功能/架构观察和独立实现建议。
- 直接采用前记录归属、通知、源码披露、专利和网络分发义务；高风险情况交法务审核。

## 采用结论模板

1. **判断**：直接采用 / 边界适配 / 独立实现 / 不采用。
2. **借鉴单元**：精确到数据合同、状态机、交互、模块边界或工程门禁。
3. **不借内容**：与当前产品冲突、平台锁定、证据不足或许可不清的部分。
4. **最小试验**：一条主链、一个真实输入、一个可检验产物。
5. **成功/退出条件**：用可观察结果而非“感觉不错”表达。
