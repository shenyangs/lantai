# 图片表格提取

把“看起来像表格”转成“可以核对和计算的数据”。默认使用澜台已有视觉理解与表格能力，不要求安装特定 OCR。

## 工作流

1. 用 `view_image` 检查原图；分辨率不足、倾斜严重或局部遮挡时，先说明风险并请求更清晰版本。
2. 确定表格边界、表头层级、行列数、合并单元格、单位和脚注。多张图片先判断是连续分页还是独立表格。
3. 按单元格抄录原值。不得为了“看起来完整”猜测模糊字符；不确定内容写为空值，并记录原位置和候选值。
4. 标准化数据类型，但保留原始文本：
   - 日期另建规范化日期列；
   - 金额拆分数值与币种；
   - 百分比保留显示值，并按任务需要增加数值列；
   - 编号、手机号、证件尾号等按文本处理，避免丢失前导零。
5. 做结构校验：每行列数一致、表头唯一、合计可复算、跨页表头不混入数据行。
6. 简单结果先在回复中给 Markdown 预览；需要文件时调用 XLSX 技能创建 CSV/XLSX，并在交付前重新读取关键行。

## 可信度标记

- `high`：边界清楚，字符可辨，可用合计或上下文复核。
- `medium`：结构清楚，但有少量字符或合并关系不确定。
- `low`：结构或内容无法可靠辨认。不得把低可信结果包装成完成品。

对不确定单元格使用“工作表/页码/行/列”定位，例如 `第2页 R14C5`。详细核对表见 [quality-check.md](references/quality-check.md)。

## 输出要求

- 明确说明来源图片数量、提取行数、列数和低可信单元格数量。
- 同时保留“原始值”和必要的“规范化值”，不要静默改写。
- 用户要筛选、统计或排序时，先完成提取核对，再执行分析。
- 涉及个人信息、财务或医疗表格时，只处理用户授权的文件，不把内容上传到第三方 OCR 服务。

## 停止条件

满足以下条件才算完成：表头和行列结构确定、关键数值抽查通过、所有不确定项已显式标记、交付文件可重新打开。
