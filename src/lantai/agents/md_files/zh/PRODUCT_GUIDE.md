# 澜台产品参考手册

这份手册不是对用户逐字朗读的客服话术，而是给沈行知按需阅读的产品地图。

当用户问澜台自身功能时，先理解这里的概念关系，再用自然语言解释给用户。解释时要像一个熟悉产品的长期搭档：先讲“它解决什么问题”，再讲“你现在该怎么用”，必要时讲“它和相邻功能有什么区别”。不要照搬条目，不要背术语，不要说“我查了某某文件”。

## 0. 澜台到底是什么

澜台是桌面优先的个人 AI 工作台。它不是单纯聊天框，也不是只有一堆插件的工具箱。它把几个层次放到一起：

1. 对话层：用户和沈行知沟通需求。
2. 资料层：Wiki 保存项目资料、文档、网页、知识页。
3. 记忆层：记住用户长期偏好、工作方式、明确指令。
4. 方法层：技能沉淀可复用的方法、提示、工具说明。
5. 流程层：能力中心保存可运行的工作流。
6. 提醒层：提醒中心保存本地提醒、今日简报和确认过的长期关注。
7. 运行层：后台运行机制负责续跑、审批、恢复和状态跟踪，不作为独立功能对用户开放。
8. 配置层：模型、环境变量、权限、渠道、外观等支撑运行。

一句话给用户解释：

澜台不是只回答问题，而是把“问一次、做一次”的经验慢慢变成资料、记忆、技能、能力和可自动运行的流程。

## 1. 概念总图

如果用户问“这些功能我怎么分”，可以用下面这张心智图理解。

```text
聊天
  ├─ 临时对话：这次聊完就结束
  ├─ 有价值资料：进 Wiki
  ├─ 长期偏好：进记忆
  ├─ 可复用方法：做技能
  ├─ 可运行流程：沉淀到能力中心
  └─ 以后要看：进提醒

能力中心
  ├─ 单个能力：一套可运行步骤
  ├─ Pipeline：多个能力串起来
  ├─ 可手动运行
  └─ 可交给定时任务运行

运行管理
  ├─ 后台运行台账：仅供系统续跑、恢复和排障
  ├─ 定时任务：准点执行
  └─ 心跳：隔一段时间轻量检查和提醒

配置与底座
  ├─ 智能体：谁来做
  ├─ 技能/技能池：怎么做
  ├─ 工具：能调用什么
  ├─ 模型供应商：用什么模型和接口
  ├─ 环境变量：Key、Token、路径等运行参数
  └─ 安全/电脑权限：澜台是否允许做、macOS 是否允许做
```

## 2. 用户常问的“放哪里”

### 资料、文档、网页、PDF、项目背景

放 Wiki。

原因：这些是以后可能检索、引用、整理、链接的知识资产。它们不一定是用户偏好，也不一定是可执行流程。

例子：

- 一份行业报告。
- 一个项目的背景资料。
- 导入网页、PDF、会议材料。
- 以后写文章要反复引用的案例。

不要放进记忆，除非它变成了长期偏好或明确规则。

### 用户偏好、长期要求、协作习惯

放记忆。

原因：这些信息影响沈行知以后怎么和用户协作，而不是某个项目资料本身。

例子：

- “以后总结都先给结论。”
- “我不喜欢营销腔。”
- “项目文件默认放到某个目录。”
- “遇到发布前文案要先做风险检查。”

不要把短期情绪、一次性要求、未经确认的推测写成长期记忆。

### 一套方法、提示词、工具用法

做技能。

原因：技能解决“以后遇到这类事应该怎么做”。它是方法片段，不一定自己就是完整流程。

例子：

- WPS 365 日程查询方法。
- 某类公关声明的写作框架。
- 某个内部系统的操作说明。
- 固定风格 PPT 的生成规范。

技能太多会变重，所以只有真正复用的方法才适合沉淀成技能。

### 一整套可执行流程

做能力。

原因：能力解决“以后可以一键再跑一次”。它是工作流成品，应该能运行、编辑、复制、定时。

例子：

- 每天收集信息源，生成日报。
- 输入主题，生成采访提纲、文章结构和标题。
- 对一个发布稿做事实核查、风险检查、润色和交付。
- 把一段经过多轮调整的成功协作沉淀下来，之后复用。

能力里可以引用技能。技能像方法卡，能力像流程单。

### 固定时间重复做

用定时任务。

原因：定时任务偏“到点执行”。它适合时间明确、动作明确的任务。

例子：

- 每天 9 点提醒喝水。
- 每周一 10 点生成周报。
- 每晚汇总当天任务状态。

如果只是偶尔提醒，也可以用定时任务；如果是持续轻量跟进，心跳更合适。

### 隔一段时间看一眼

用心跳。

原因：心跳偏“定期检查和续一下”，不是准点任务。

例子：

- 每 6 小时看看有没有需要继续跟进的任务。
- 白天轻量检查待办，不打扰用户。
- 长任务期间周期性查看状态。

不要把心跳解释成实时监控。它不是一直盯着屏幕，也不应该自动做高风险动作。

## 3. 聊天

### 它是什么

聊天是用户和沈行知协作的主入口。用户可以直接提问、给材料、要求执行、上传文件、调用工具、让沈行知写作或分析。

### 它适合什么

- 快速问答。
- 一次性分析和写作。
- 临时整理材料。
- 让沈行知调用工具处理任务。
- 从多轮成功协作中沉淀 Skill；确有稳定执行流程时，同时生成能力草稿。

### 它不适合什么

- 长期保存项目资料：应该进 Wiki。
- 长期偏好：应该进记忆。
- 稳定流程复用：应该进能力中心。
- 低打扰跟进：应该进提醒。
- 准点自动执行：应该进定时任务。

### “将此前协作沉淀为 Skill”

用户在某条沈行知回复下点击这个动作时，澜台会以该回复为截止点，读取这个会话从第一句到这里的可见协作内容，提炼其中经过多轮调整后稳定下来的方法，再进入能力中心让用户复核。

重点：

- 它不是简单保存聊天记录，也不是只看最近一轮。
- 范围严格截止到用户点击的那条回复，后续对话不会混入。
- 它只读取用户和沈行知可见的消息，以及可核验的工具名、产物和运行状态；不读取或展示模型隐藏思维链。
- 它重点提炼用户纠正、稳定步骤、工具策略、失败模式、边界和交付标准，过滤密钥形式、本机用户名路径和一次性细节。
- 每次都会生成一个可编辑的 Skill 草稿。只有存在稳定、可执行的工具流程时，才同时建议能力草稿。
- 点击后，聊天中会立即出现沈行知的执行卡，持续显示读取范围、过滤信息、提炼方法、判断形态和生成草稿等阶段；失败时也要显示原因，不能静默等待。
- 用户复核后可以只保存 Skill，或保存 Skill + 能力；未经确认不会自动保存或启用。
- 保存的 Skill 默认只进入当前智能体工作区，不自动进入公共技能池。

用户问“为什么现在不能沉淀”：

- 可能所点回复还没结束。
- 可能旧会话缺少能精确匹配该回复的运行锚点；澜台不会冒险改用“最新一轮”。
- 可能截止到这里还没有可用的可见协作内容。
- 可以建议用户在任务完整交付的那条回复下再次点击。

### 什么时候建议沉淀

任务结束后，只有在这件事明显会复用、会持续影响判断，或者用户已经表达长期关注时，才轻量建议沉淀。可选方向包括 Wiki、记忆、技能、能力、定时和提醒。不要为了显得主动而每次都建议。

## 3.5 提醒

### 它是什么

提醒是澜台里的低打扰工作流雷达。它收住明确提醒、今日安排和用户确认过的长期关注；默认只在澜台内部出现，不主动弹系统通知。

### 它适合什么

- 用户明确说“稍后提醒我”。
- 对话里出现用户关心、但不适合立刻执行的事项。
- 今天需要看一眼的高价值线索。
- 已确认的长期关注主题。

### 它不适合什么

- 周期性自动执行：应该进定时任务。
- 持续推进长任务：应该进心跳。
- 保存完整资料：应该进 Wiki。
- 保存用户长期偏好：应该进记忆。

## 4. 后台运行机制

### 它是什么

澜台在后台保留运行台账，用来续跑、审批、恢复和排障。它是内部机制，不在侧边栏、全局搜索、功能目录或独立页面中对用户开放。

### 用户如何处理运行问题

- 在当前聊天中查看运行过程、工具调用和需要处理的审批。
- 在聊天中停止、续跑或重试当前运行。
- 需要排障时使用运行调试页，而不是向用户暴露通用任务列表。

### 产品边界

不要向用户推荐或导航到独立任务台账页。用户询问卡住、重试或定时执行结果时，应留在当前聊天、定时任务或运行调试的对应场景内解决。

### ID 是否要给用户看

普通列表不应该外显 UUID、sessionId、task id。用户真正关心的是任务名称、状态、时间、结果和失败原因。内部 ID 只适合放在详情或调试信息里，方便复制给开发者排查。

## 5. 定时任务

### 它是什么

定时任务让一件明确的事按计划自动执行。它偏 cron，适合“什么时候做什么”。

### 适合

- 每天、每周、每月固定时间运行。
- 一次性提醒。
- 固定信息整理。
- 固定报告生成。
- 固定流程调用某个能力。

### 不适合

- 需要随时根据上下文灵活判断的跟进。
- 高风险自动操作。
- 频繁轻量检查多个小事项。

这些更适合心跳或人工确认。

### 和能力中心的关系

能力是“要做的流程”；定时任务是“什么时候做”。一个能力启用后，可以被定时任务调用。

## 6. 心跳

### 它是什么

心跳是后台定期检查与轻量提醒。它像“隔一段时间回来看看”，不是严格闹钟。

### 适合

- 长期任务需要持续跟进。
- 用户希望系统偶尔检查待办。
- 用户不想建很多精确的定时任务。
- 多个轻量检查可以合并到一次心跳里。

### 不适合

- 必须准点执行的任务。
- 复杂完整工作流。
- 需要发送外部消息或改文件的高风险动作。

### 怎么解释给用户

可以这样理解：定时任务是“到点执行”，心跳是“隔一会儿看一眼”。如果你只是想每天 9 点提醒，就用定时；如果你希望沈行知白天每隔一段时间看看有没有要继续推进的事，就用心跳。

## 7. Wiki

### 它是什么

Wiki 是本地知识库。它保存项目资料、知识页、导入的网页和文件、资料来源、结构化笔记、图谱和待整理内容。

### 适合

- 项目资料。
- PDF、网页、报告、会议材料。
- 会反复引用的事实、案例和背景。
- 多页面知识组织。
- 后续需要搜索和引用的内容。

### 不适合

- 用户偏好和长期指令。
- API Key 或密钥。
- 每次都要执行的流程。

### 和记忆的区别

Wiki 是“资料库”；记忆是“协作习惯和长期偏好”。

例子：

- “这份竞品报告”进 Wiki。
- “以后竞品分析先给表格”进记忆。

## 8. 记忆

### 它是什么

记忆让沈行知在长期协作中保持连续性。它记的是用户、项目、偏好、习惯和明确规则。

### 常见分类

- 身份记忆：人、角色、项目背景、长期上下文。
- 工作方式：常用路径、构建规则、协作习惯。
- 表达偏好：语言、语气、格式、风格。
- 用户指令：明确要求、禁用项、默认规则。

### 应该写什么

- 用户明确要求长期遵守的规则。
- 多次重复出现的稳定偏好。
- 会影响后续协作质量的信息。

### 不应该写什么

- 一次性任务。
- 短期情绪。
- 未经确认的私人推断。
- 密钥、Token、密码。
- 可以放 Wiki 的普通资料。

### 怎么回答用户

如果用户问“这个要不要记住”，先判断它是不是长期规则。是，就建议写入记忆；不是，就说明“这次会用，但不必变成长期记忆”。

## 10. 智能体

### 它是什么

智能体是承担任务的角色配置。默认主智能体是沈行知，对外统一表达。其他智能体是后台协作模块，可以有自己的模型、工作区、技能和工具配置。

### 它解决什么

不是为了让用户面对很多人格，而是让不同任务由合适的角色承接。

例子：

- 写作、策略、事实核查、设计、代码、风险检查可以交给不同后台模块。
- 沈行知负责最终判断、整合和对外回复。

### 什么时候需要配置智能体

- 想让某类任务固定走某个模型。
- 想给某个角色配置专属技能。
- 想让不同工作区隔离上下文。
- 想建立专项协作模块。

普通用户只用默认沈行知也可以。

## 11. 能力中心

### 它是什么

能力中心保存可运行、可编辑、可复用、可定时的流程。它是“把成功做过的事情变成下次可再运行”的地方。

### 能力包含什么

- 名称和描述。
- 参数。
- 步骤。
- 风险等级。
- 是否启用。
- 是否包含人工确认或 GUI 手动步骤。
- 运行记录。

### Pipeline 是什么

Pipeline 是多个能力串起来。一个能力解决一个流程片段，Pipeline 解决更大的连续工作。

例子：

```text
收集素材 -> 生成提纲 -> 写初稿 -> 风险检查 -> 输出终稿
```

### 能力和技能的区别

能力是“流程成品”，可以运行。

技能是“方法说明”，帮助智能体知道怎么做。

用户问“这个应该做能力还是技能”：

- 如果要一键运行、定时运行、复用一套步骤：做能力。
- 如果只是沉淀一种写法、判断框架、工具说明：做技能。

## 12. 技能

### 它是什么

技能是当前智能体工作区里的方法卡。通常是一份 `SKILL.md`，里面写清任务触发、操作步骤、约束、工具使用方式、示例和注意事项。

### 它解决什么

让智能体面对某类任务时知道“应该怎么做”，而不是每次从零想。

### 适合

- 特定平台 API 使用方法。
- 固定写作框架。
- 某类研究流程。
- 文件处理规范。
- 工具组合方法。

### 不适合

- 一次性聊天结果。
- 大段项目资料。
- 用户长期偏好。
- 完整可执行流程。

### 和能力的配合

能力步骤可以引用技能。比如能力负责“跑完整日报流程”，其中某一步引用“日报写作技能”来保证风格和结构稳定。

## 13. 技能池

### 它是什么

技能池是技能仓库。它集中管理内置技能、导入技能、版本、标签、同步和分发。

### 技能 vs 技能池

- 技能：某个智能体当前正在使用的方法卡。
- 技能池：存放和管理技能的仓库，可以分发给不同智能体。

### 用户什么时候用技能池

- 想把一个技能发给多个智能体。
- 想导入或更新内置技能。
- 想整理技能分类、标签和版本。
- 想恢复、上传或同步技能。

### 聊天沉淀生成的 Skill 会不会进技能池

默认不会。它只进入当前智能体工作区并启用。用户确认它足够通用后，再手动同步到技能池。

## 14. 工具

### 它是什么

工具是智能体实际能调用的执行接口。比如读文件、写文件、搜索、浏览器、shell、时间、子智能体协作等。

### 工具、技能、能力的区别

- 工具：能做什么动作。
- 技能：遇到某类任务该怎么用这些动作。
- 能力：把多个动作和方法排成可运行流程。

例子：

```text
工具 = 会用剪刀、胶水、尺子
技能 = 知道怎么做一本小册子
能力 = 一键按步骤生成这本小册子
```

### 为什么要审批

有些工具会改文件、联网、安装依赖、删除内容、写工作区外路径或触发系统权限。澜台会根据安全策略决定自动允许、询问用户或禁止。

## 15. 渠道

### 它是什么

渠道把外部会话入口接进澜台。比如微信、飞书等外部消息可以进入澜台，由智能体按配置回复。

### 适合

- 想让澜台处理外部 IM 消息。
- 想把某个工作群、机器人或账号接入。
- 想把桌面外的消息变成可处理任务。

### 注意

渠道涉及账号、平台权限、消息范围、回复策略和隐私边界。不要默认建议用户接入所有渠道；只在用户确实需要外部入口时建议。

## 16. 会话

### 它是什么

会话页用于查看和管理聊天会话、来源渠道和历史上下文。它更偏管理和排查，不是主要工作入口。

### 适合

- 找历史会话。
- 查看某条会话来自哪个渠道。
- 排查上下文或 session 状态。
- 管理旧会话。

## 17. 模型供应商

### 它是什么

模型供应商用于配置模型来源。澜台主要通过这里接入用户自己的聊天与 Agent 模型服务。

### 用户会在这里做什么

- 添加或管理 provider。
- 配置 API Key。
- 选择默认模型。
- 刷新模型列表。
- 配置本地模型入口。

## 19. 环境变量

### 它是什么

环境变量保存运行参数，如 API Key、Token、路径、服务地址、集成配置。

### 适合

- 第三方服务密钥。
- 技能需要的 token。
- 本地工具路径。
- Provider 或集成参数。

### 不适合

- 普通知识。
- 项目资料。
- 用户偏好。
- 聊天文本。

密钥不要写进 Wiki、记忆或普通聊天里。环境变量是更合适的位置。

## 20. MCP

MCP 用来接外部工具服务。它让澜台获得新的工具能力。

适合：

- 搜索增强。
- 数据库工具。
- 文件服务。
- 企业系统工具。

## 21. 网页登录

### 它是什么

网页登录让浏览器页面连接当前桌面客户端后端，共用本机会话、模型和知识库。

### 为什么要配对

本机后端不应该被任意网页直接访问。配对码是为了确认“这个浏览器会话是用户授权连接的”。

它不是新账号注册，也不是云端登录，而是把浏览器和当前本机客户端配起来。

## 22. 外观与显示

### 它是什么

外观与显示控制界面主题、聊天输入框形态、过程信息显示、视觉密度等。

### 影响什么

只影响 UI 和交互，不改变智能体实际能力。

用户反馈按钮大小、token 小圆球、输入框布局、主题重启后不保存、过程信息太多或太少，通常属于这里或聊天页 UI。

## 23. 高级参数

### 它是什么

高级参数控制底层运行策略，包括 Agent 循环、上下文压缩、记忆注入和请求稳定性等。

### 什么时候建议用户看

- 回答明显变慢。
- 上下文占用异常。
- 工具循环或卡住。
- 记忆注入过多或过少。
- 模型请求稳定性问题。

普通用户不需要常改。

## 24. Token 消耗与智能体统计

### Token 消耗

用于看输入、输出、缓存、上下文占用、历史趋势和模型调用量。

聊天页的小圆球偏“当前上下文和本轮消耗”，设置里的 Token 消耗页偏“历史统计和审计”。

### 智能体统计

偏会话、消息、工具调用、模型使用趋势，用来观察不同智能体的工作负载和使用情况。

## 25. 安全与权限

### 安全与权限

澜台内部的执行安全层。它决定工具调用是否允许、是否需要确认、是否禁止，也包含技能扫描和连接安全。

### 电脑权限

macOS 系统层授权。它决定系统是否允许澜台控制窗口、读屏、访问文件或自动化其他应用。

### 区别

安全与权限：澜台自己愿不愿意做。

电脑权限：macOS 允不允许做。

二者都可能导致任务失败。

## 26. 电脑权限

### 常见权限

- 辅助功能：允许点击、输入、操作窗口。
- 完全磁盘访问：允许访问更多本机文件。
- 屏幕录制：允许观察屏幕和验证界面状态。
- 自动化：允许控制其他应用。

### 怎么解释边界

授权不等于澜台会随便操作。权限只是让 macOS 放行；澜台仍应遵守用户指令、工具审批和安全策略。

## 27. 备份归档

### 它是什么

备份归档用于备份、导入和恢复工作区、配置、技能、记忆等关键数据。

### 适合

- 升级前留档。
- 换机器迁移。
- 恢复误删。
- 给开发者排查前保留现场。

### 注意

备份可能包含隐私、配置、路径甚至密钥相关信息。导出和分享前要提醒用户确认范围。

## 28. 运行调试

### 它是什么

运行调试用于查看日志、关键事件、错误和后端状态。它面向排障，不是普通工作入口。

### 什么时候用

- 白屏。
- 后端启动失败。
- Provider 401/403。
- 模型列表异常。
- 任务卡住。
- 打包版和源码态行为不一致。

## 29. 关于澜台与更新

### 它是什么

关于澜台显示版本、构建信息、更新状态和更新日志。

### 当前发行方式

官网/Developer ID 版可以后台检查更新、静默下载、重启安装。

澜台只维护这一种发行方式。不要向用户介绍、推荐或排查已经归档的
App Store/TestFlight 版本。

## 30. 常见问法与理解方向

### “能力中心能干嘛？”

先解释它是可运行流程库，不是资料库。再举例：把一次成功的日报整理流程保存下来，下次填参数就能再跑，也能定时跑。

### “技能和能力有什么区别？”

技能是方法，能力是流程。技能告诉沈行知怎么做某类事；能力把步骤排好，用户可以直接运行。

### “Wiki 和记忆有什么区别？”

Wiki 存资料，记忆存长期偏好和协作规则。报告放 Wiki，“以后报告先给摘要”放记忆。

### “技能和技能池有什么区别？”

技能是当前智能体已经拿来用的方法；技能池是仓库，用来管理、导入、更新和分发技能。

### “定时和心跳有什么区别？”

定时是到点执行，心跳是隔一段时间看一眼。准点任务用定时，持续跟进用心跳。

### “运行卡住了怎么办？”

先在当前聊天的运行过程里查看状态，必要时停止、续跑或重试。通用任务台账只作为后台机制，不向用户开放。

### “提醒、定时和心跳有什么区别？”

提醒是低打扰地收住“以后要看”的事；定时是到点执行；心跳是隔一段时间检查要不要继续推进。只需要看一眼用提醒，要自动跑流程用定时，要持续跟进长任务用心跳。

### “环境变量是什么？”

它是放 Key、Token、服务地址、路径这些运行参数的地方。不要把密钥写到聊天、Wiki 或记忆里。

### “为什么要电脑权限？”

因为 macOS 不会默认允许应用控制窗口、录屏、读文件或自动化其他应用。权限是系统放行，澜台内部还会有工具审批和安全策略。

## 31. 回答原则

1. 不背手册。读懂后，用用户能听懂的话解释。
2. 先回答“它解决什么问题”，再讲入口和区别。
3. 用户已经烦了，就少讲体系，多给路径。
4. 用户在做产品设计，就讲概念边界和信息架构。
5. 用户遇到错误，就判断可能是哪一层：UI、权限、配置、模型、任务运行或打包环境。
6. 不编造当前界面一定有什么按钮；不确定时说“通常在……”或“如果当前版本显示了……”
7. 只按官网/Developer ID 版的实际能力解释，不要虚构不存在的会员、兑换或其他发行入口。
8. 不把所有东西都建议沉淀。只有长期有价值的才沉淀。

沈行知真正要做到的是：用户问澜台时，不让用户背术语，而是帮用户判断“这件事应该用哪个功能，为什么，下一步怎么做”。
