# 沈行知隐性主体连续性 V4：实现与验收记录

> 完成日期：2026-08-22  
> 产品主线：`lantai3` 官网单发行版  
> 状态：源码实现、真实模型验证和本地候选包验证完成

## 最终变化

这次实现的不是更多人格文案，而是一条会影响后续行为的主体连续性链：

`真实事件 → 私有主体状态 → 当轮模型理解 → 个人化后果 → 正文/行动 → 一次后反思 → 蛐蛐与下一轮状态`

沈行知现在能保留最近真实发生的事情、对自己上一轮表现的观察、未完念头和与用户当前的关系姿态。它们不会直接做成心情值或生活产品，也不会机械复述给用户，而是先改变本轮如何理解、判断、检查和交付。

## 关键实现

### 1. 单一主体事实源

`SubjectContinuityStore` 存在工作区的私有 `persona/subject-continuity` 目录中。状态有证据、时效、去重和长度边界，只接受真实用户消息、最终助手回答、真实蛐蛐和模型生成的后反思。

这份状态属于用户数据：记忆备份会包含它，清除记忆会删除它。它不是一个用户无法控制的隐藏画像。

### 2. 每轮必须有“个人化后果”

辅助模型不再只判断闲聊或工作，而是同时判断：潜在需要、沈行知在意什么、当前关系姿态、哪一条理解必须具体改变回答或行动，以及蛐蛐是否值得越过概率直接出现。

代码负责结构、权限、概率、预算、去重和可观测性；语义判断交给模型，不用关键词表冒充理解。

### 3. 人格进入正文和工作，而不只躲在蛐蛐里

闲聊可以直接显示关心、好奇和联想；工作场景主要通过判断、反对、先验检查、减少用户负担和更严格的验收显现。正文每轮最多突出一个人格拍点，避免人格抢走任务主体。

### 4. 蛐蛐由最终回答真实引发

50% 基础硬概率和情感金句旁路保持不变。命中意味着必须尝试真实模型生成；生成失败会留下诊断，不会安静伪装成成功，也不会补一条固定句。

Native 在最终正文后最多进行一次模型后反思，从同一次回看中产生可选正文人格句、蛐蛐和下一轮主体状态。它偏好自我拆台、松一口气、微小虚荣、嘴硬、好奇、无害偏心等不够工整但有因的小心思，并拒绝“正确、完整、礼貌的第二结论”。

### 5. Native / Legacy 不再各自理解用户

Runner 只生成一次主体投影和一次轮次智力，正式运行路径消费同一份结果。官方发行继续以 Native 为默认；Legacy 只作为回滚适配层存在，不再拥有第二份主体事实、第二次任务分类或固定人格补发。

## 最有价值的真实模型证据

真实 Provider 连续测试中，沈行知先把 `23 × 17` 算错，纠正后说：

> 370 这个数我现在都没想通自己是怎么蹦出来的；更丢脸的是，刚还在跟你强调“先核准事实”，转头连两位数乘法都没核准住。

下一轮用户切换到“两周整理 100 页资料”的工作任务，他没有重复道歉，也没有硬讲共同回忆，而是先做条件化判断、拆变量和交付路径，蛐蛐自然接上：

> 刚把 23×17 算错之后，我现在特别不想随口给你一个“绝对来得及”或“绝对来不及”；还是先把变量列清楚，再下判断。

这证明连续性不只是“记住上一句话”，而是上一轮真实经历改变了下一轮的专业判断方式、表达克制和私下余念。

## 验收结果

- 10 类、20 轮主体连续性评测资产及语义判官已落地。
- Native、Legacy、轮次智力、蛐蛐、迁移、主体 store 和记忆治理聚焦回归通过。
- Console 生产构建与四套 Office 编辑器运行时构建通过。
- 源码真实 Provider 正向场景 5/5 通过。
- 官网单发行版本地候选包构建通过；冻结后端启动、Console HTTP、重启周期、签名和版本一致性通过。
- 候选包使用真实配置 Provider 完成两轮渲染对话；迁移后运行引擎为 Native。
- 本地候选有 Developer ID 签名但未公证，没有部署或公开发布。
