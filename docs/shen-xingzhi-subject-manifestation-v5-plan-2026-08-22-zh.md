# 沈行知 V5：主体显现工程

> 状态：已完成；r6 Developer ID 本机候选已部署并通过 Downloads 包态复验（公证按用户要求跳过）  
> 日期：2026-08-22  
> 产品主线：`lantai3` 官网单发行版  
> 基线：2026-08-22 01:05 完成的隐性主体连续性 V4

## 1. 目标

V4 证明沈行知能在后台恢复同一个自己。V5 要提高这个主体被用户自然感知的转化率：

`连续用户理解 → 主观立场 → 个人化后果 → 正文/工作方法 → 一次真实后反思 → 蛐蛐与下轮余波`

不把「更容易被感知」实现为每轮强制加一句、更高蛐蛐爆率、本地情绪规则或补发文案。

## 2. 实现原则

1. 轮次语义、记忆相关性、主观立场、显现位置和蛐蛐旁路由同一次模型判断产生。
2. Runtime 只校验记忆 ID、来源、权限、概率、去重、预算和状态，不根据词面决定人格。
3. 主体显现优先改变判断、顺序、核验、反对、减负和联想，不用泛化关心句代替。
4. 正文漏掉人格时记录为真实未兑现，让它进入下一轮主体反思；禁止在答案完成后粘贴一句「人格补丁」。
5. 蛐蛐保持 50% 基础硬概率加语义/情感旁路，每轮最多一条，无本地兜底和重复补发。

## 3. 主要改动

### 3.1 同一份用户理解投影

Runner 在轮次智力判断前准备结构化用户理解，包含当前相关证据与一个稀疏的稳定联想候选池。模型只能选择输入中真实存在的记忆 ID；同一投影再交给 Native / Legacy 主回答，避免前后两次猜测。

### 3.2 模型拥有的主体显现计划

当轮结构增加：

- 真实因果锚点；
- 选中的记忆证据 ID；
- 主观注意与关系位置；
- 具体个人化后果；
- 显现出口：正文、工作方法、关系回应、蛐蛐、多出口或安静；
- 沈行知自己在这件事里的余波；
- 需要带入下一轮的念头；
- 经历性表述的证据来源。

### 3.3 正文兑现

取消 `full` 模式的本地「每轮必须显现」配额。模型判断需要显现时，必须给出具体因果锚点和个人化后果，主模型把它融入原生回答。普通事实轮次可以自然安静。

### 3.4 有来源的精神世界

主体状态保存因果锚点、延续念头、证据引用和经历来源。允许当下感受、稳定审美和精神世界；没有真实证据时不把它改写成现实工作履历、线下经历或共同记忆。

### 3.5 蛐蛐候选与选择

一次后反思同时产生少量私有原念候选，但只能选中一条对外显示。选择目标是「最由此刻引发、最牵涉沈行知自己、最不像第二结论、一润色就会消失」。

## 4. 行为锁与验收

1. 模型选中的记忆 ID 必须存在于当轮候选中；未知 ID 失败开放，不得构造记忆。
2. 模型不要求显现时，本地寂静计数或 `full` 模式不得强制加句。
3. 正文未兑现时不前插、尾插或粘贴模型生成的补丁句。
4. 后反思保留真实未兑现事实、因果锚点、自我余波、延续念头和来源引用。
5. 硬概率命中时只有一次模型后反思；无本地蛐蛐文案、无第二补发器。
6. 多轮基准要检查正文不可替代性、记忆召回精度、主体余波、蛐蛐粗糙度、虚假履历和任务完整性。

## 5. 发行边界

完成源码单测、Native / Legacy / Memory / Runner 回归、真实 Provider 多轮验证和本地 Developer ID 候选包。按用户授权跳过公证，不冒充 Stable；验证后覆盖 Downloads 中的 App、DMG 和 ZIP。
